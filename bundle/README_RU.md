# Перенос SO-101 leader + follower и телеуправления

Комплект от 23.10.2026 для тех же физических рук и USB-контроллеров. Камера и её калибровка находятся в отдельном экспорте SO101_export_2026-10-20 и для этого телеопа не требуются.

## Что сохранено

- `so101_follower_calibration.json`: ID, нулевые смещения, диапазоны рабочей руки.
- `leader_setup/so101_leader_calibration.json`: ID, нулевые смещения, измеренные диапазоны джойстика.
- `leader_setup/`: журнал назначения ID, исходные смещения и результаты записи диапазонов. Это данные, не программы повторной настройки.
- `teleop_so101.py`, `serial_protocol.py`, `verified_telemetry.py`: актуальные программы управления и проверки связи/состояния.
- `teleop_config.json`: порты, скорость и длительность по умолчанию.
- `motor_parameters.json`: сохранённые параметры и пояснения к настройкам моторов.
- `install_usb_access.sh` и `99-so101-teleop.rules`: установка доступа к обоим конкретным USB-контроллерам на новом Linux-компьютере.

Для этих же рук ID и смещения уже записаны в EEPROM моторов, сохраняются после отключения и не требуют повторного назначения. Перенос файлов не переписывает EEPROM. При замене моторов, контроллеров или механики нужна отдельная проверка/калибровка. Пределы follower проверяются программой по EEPROM. Калибровку leader нельзя заменять калибровкой follower.

## Установка на Ubuntu/Debian

Скопируйте всю папку, откройте терминал в ней:

```bash
sudo apt install python3-venv python3-pip acl
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -B verify_bundle.py
bash install_usb_access.sh
```

Последняя команда с sudo устанавливает постоянное правило доступа именно для этих двух контроллеров. Переподключите USB, если права не обновились. Скрипт сам не запускает моторы.

Leader: серийный номер 5B79016829. Follower: 5B8E114736. Устройства определяются по `/dev/serial/by-id`, номера ttyACM0/1 могут меняться. При другой ОС пути и механизм прав потребуется адаптировать; этот комплект рассчитан на Linux.

При разовом отказе доступа вместо постоянного правила можно дать временный доступ:

```bash
sudo setfacl -m "u:$(id -un):rw" /dev/serial/by-id/usb-1a86_USB_Single_Serial_5B79016829-if00
sudo setfacl -m "u:$(id -un):rw" /dev/serial/by-id/usb-1a86_USB_Single_Serial_5B8E114736-if00
```

## Проверка без движения

```bash
python -B teleop_so101.py --resume-holding
```

Проверяются модели, ID, смещения, диапазоны follower, момент, питание и температура. По умолчанию программа не включает момент и не отправляет команды движения. `--resume-holding` разрешает подключаться к уже удерживающей позу рабочей руке; джойстик должен оставаться с выключенным моментом. Закройте другие программы, занимающие порты.

## Запуск

Закрепите основание, освободите путь движения руки и держите джойстик неподвижно при начальном выравнивании. При включении моторов рука должна быть в устойчивой поддерживаемой позе. Начинать проверку лучше с пустым захватом.

```bash
python -B teleop_so101.py --execute --full-range --resume-holding --seconds 60 --speed 400
```

Рука сначала плавно идёт в позу джойстика со скоростью цели 40 отсчётов/с. Затем следует абсолютным углам суставов, ограниченным калибровкой. Для захвата сопоставляется доля открытия в измеренном диапазоне. Предел скорости моторов после выравнивания 400 отсчётов/с (около 35°/с); реальная скорость зависит от нагрузки и ускорения. Программного сглаживания после выравнивания нет; `--smooth-tracking` включает его. `--relative` возвращает режим движения от стартовых поз без их выравнивания.

Для сеанса до пяти минут замените `--seconds 60` на `--seconds 300`. Используйте ограниченные сеансы; непрерывный режим не проверялся и не рекомендован этим комплектом.

Закрывание захвата может остановиться на предмете: через две секунды это определяется как предполагаемый контакт, а не авария слежения. Это не датчик контакта. Контроль открытия, нагрузки, температуры и аппаратных ошибок остаётся активным. Предел усилия захвата не повышен.

При аномальной температуре новые цели временно не отправляются; требуются три стабильных чтения ниже 45 °C. Устойчивая высокая температура, ненормальное питание/нагрузка, аппаратные ошибки или отсутствие прогресса других суставов останавливают телеоп. Не используйте журнал как подтверждение физической безопасности.

## Остановка

Ctrl+C или таймер прекращают телеоп и переводят follower в удержание. Это не аварийное отключение питания; момент остаётся включённым. Для снятия момента сначала поддержите руку и предмет или поставьте их на опору, завершите телеоп, затем:

```bash
python -B disable_torque.py --supported
```

Не запускайте снятие момента одновременно с телеопом. В случае ошибки проверьте `leader_setup/teleop_last_run.json`; он создаётся на новом компьютере и содержит последние цели, телеметрию и события. После повторяющихся аппаратных ошибок проверьте питание и соединения перед повторным запуском.

## Проверка комплекта

`verify_bundle.py` сверяет SHA256, JSON и синтаксис Python без открытия устройств. Проверены комплектность и программные сценарии текущего кода; физический запуск перенесённого комплекта на другом компьютере не выполнялся. После изменения файлов контрольные суммы перестанут совпадать — это ожидаемо. Виртуальное окружение нужно создать заново, оно не переносится.
